## Decision register

Project owners must decide the following without engineering inference:

1. Hosting provider or self-hosted environment, network boundary, TLS operator, and named operational owner.
2. Enterprise identity provider, MFA, account provisioning and session revocation policy, or approval limited to local controlled demo accounts.
3. Evidence classification, permitted evidence, encryption and key ownership, retention/deletion/legal hold, and who can access backups.
4. Backup frequency, backup encryption, recovery-point objective, recovery-time objective, and restore authority.
5. Malware scanner, quarantine boundary, release decision owner, outage behavior, and acceptable scan latency.
6. Whether an external integration is required and, if so, target, API contract, source/destination permissions, and sandbox.
7. Independent analysis acceptance thresholds and evaluator-labeled permitted data.
8. Expected concurrency, availability, latency, storage volume, and performance acceptance targets.
9. Alert destination, on-call/support process, incident response, audit/log retention, and CI branch protection.

A READY status never extends beyond the evidence and environment stated in its row. In particular, controlled local demo readiness does not imply staging or production readiness.

The owner decision register expands these topics into 17 individual decisions with supported options, assumptions, operational implications, owner roles, and blocking scope: [DRILLLOOP_OWNER_DECISIONS.md](DRILLLOOP_OWNER_DECISIONS.md). No organization-specific choice is inferred from source code.
