## Decision summary

- The new 12-slide Business Review is generated from a new source file using original text and native PowerPoint shapes. It does not open or copy the former deck, its masters, layout, fonts, or assets.
- The new deck uses Noto Sans from a pinned Google Fonts revision under SIL Open Font License 1.1. The generator downloads and verifies the font and license in a temporary directory. No standalone font file is added to this repository; the PPTX references the font, while the PDF contains an embedded subset for rendering.
- No photographs, screenshots, external icons, logos, decorative artwork, or imported diagrams are used in the replacement deck. The name “DrillLoop” appears as ordinary text; no organization logo or organization branding is used.
- The old template-based Business Review remains in the existing release commit and public Git history until a separately authorized follow-up commit replaces it. Its template and embedded font rights are not cleared by this register.
- Idea Document and Pitch Deck screenshots, existing PDF font subsets, and authorship/brand ownership still need owner confirmation. The Business Case contains text and vector elements only and references PDF base fonts without embedding font programs; its author/ownership still needs confirmation.

All seven published artifact paths listed in the table below already exist in the `main` baseline at `78f2d594a88e5512672720f311aa8e1dceb344f1`, which Phase 10 confirmed as the public baseline. Replacing files in this worktree does not remove their earlier public versions from Git history, forks, or cached downloads.

## Historical disclosure: Pitch Deck image descriptions

Repository evidence confirms that `DrillLoop_Pitch_Deck.pptx` at public-baseline commit `78f2d594a88e5512672720f311aa8e1dceb344f1` and its earlier ancestor `6fd20166e921` each contain a developer-machine absolute path in three image-description fields on slides 3, 5, and 7. The corresponding Pitch Deck PDFs at those commits contain no matching absolute-path marker. The current release candidate contains zero such image descriptions. The earlier PPTX versions are reachable through existing Git history and may also remain in repository mirrors, cached downloads, forks, or clones; a normal follow-up commit will not erase those copies.

The values reveal a local account and nested working-directory/project labels. The review found no credential-like assignment, email address, or private/loopback endpoint in the historical package text and metadata. That is evidence about the inspected Office package, not proof that the directory labels are non-confidential. The current candidate removes the path from new-release content. No severity classification is made here.

Security owner decision required: (1) accept the historical local-directory disclosure and record the rationale; or (2) request a separate history-remediation proposal after evaluating the value of removing old refs against risks to existing clones, forks, cached artifacts, commit IDs, and collaborators. Normal updates clean the current branch tip but leave earlier reachable commits intact. Any history rewrite would require separate authorization, coordination, and remote operations; none was performed or is authorized by this task.

## Project licensing decision

No project-level `LICENSE` or `NOTICE` file exists in the reviewed commit. The owner has not selected a distribution model:

| Model | What it permits / signals | Consequences and decisions still needed |
|---|---|---|
| **A. Publicly viewable; rights reserved** | Source and documents may be visible publicly while no broad reuse license is granted. | State the rights-reserved position clearly, subject to counsel/owner confirmation. Public visibility does not grant rights to third-party content. Existing dependency and font licenses continue to apply. |
| **B. Open source** | A selected license grants defined rights to project code; a separate documentation/content license may be needed. | Content owner must choose the code license and whether docs/data/examples receive a different license. Inventory dependencies, screenshots, marks, and source material. A project license cannot grant rights owned by font designers, template providers, image creators, or cited-source owners. |
| **C. Private or organization-controlled** | Access is limited to a selected organization-controlled audience and repository policy. | Identify the owning organization, repository audience, access controls, and whether any public refs must remain. Private hosting does not itself resolve third-party rights or internal ownership/assignment. |

**Recommendation:** do not add a project license or make a public push until the content owner chooses one of these models and confirms authority over the project materials. Keep the selected model separate from third-party asset and documentation permissions.
